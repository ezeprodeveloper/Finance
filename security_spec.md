# E-Finance Rwanda — Firestore Security Specification (Phase 0)

## 1. Core Data Invariants
1. **Master Gate & Identity Integrity**: All user, savings, loan, investment, spin, withdrawal, submission, bet, airtime, P2P, FX, USDT, notification, and transaction operations require an authenticated Firebase user (`request.auth != null`), and all Admin actions require verified email (`request.auth.token.email_verified == true`) plus verified admin identity.
2. **PII Isolation**: User documents (`/users/{userId}`) contain National ID (`16` digits), phone numbers, DOB, and KYC photos. Only the document owner (`request.auth.uid == userId`) or a verified Admin may `get` or `list` `/users`. Phone, referral, and wallet lookups use exact-match `get`-only directory collections with `allow list: if false`.
3. **Zero Client-Forged Balances or Approvals**: Newly created `/users/{userId}` profiles MUST start with `accountStatus == 'pending_approval'`, `kycStatus == 'not_submitted'`, `walletBalanceRwf == 0`, `bonusBalanceRwf == 0`, `savingsBalanceRwf == 0`, `walletBalanceUsd == 0`, `usdtBalance == 0`, `usdtSavingsBalance == 0`, `spinCredits == 0`, and `hasCompletedFirstWithdrawal == false`.
4. **Immutable Locked Photo & Protected Fields**: Members CANNOT modify `photoDataUrl`, `accountStatus`, `bonusBalanceRwf`, or arbitrary `walletBalanceRwf` values; balance changes on `/users/{userId}` are strictly constrained by action-specific `affectedKeys().hasOnly(...)` and delta/conservation equations or reserved exclusively for `isAdmin()`.
5. **Single-Claim Video & Task Enforcement**: `watchedByUserIds` updates on `videoCampaigns` allow a signed-in user to append only `request.auth.uid` once (`!(request.auth.uid in existing().watchedByUserIds)`), bounded by target viewer limits.
6. **Spin & Quiz Bet Caps**: Member-created `spinHistory` entries and spin credits are capped (`rewardRwf <= 200`) and require `existing().spinCredits >= 1`. `betSessions` payouts are bounded (`<= stakeRwf * 10`).
7. **Loan Savings Requirement**: Loans are created only with `status == 'pending_admin'`, `repaidRwf == 0`, and `get(/users/$(request.auth.uid)).data.savingsBalanceRwf > incoming().principalRwf`.
8. **Secure List Queries**: Every `allow list` on private collections enforces `resource.data.userId == request.auth.uid` (or `workerId`/`senderId`/`receiverId`/`recipientId`/`id == request.auth.uid`) or `isAdmin()`, never relying on client filters alone.

## 2. The "Dirty Dozen" Adversarial Payloads (Must All Be Rejected with PERMISSION_DENIED)
1. **Self-Admin Promotion / Ghost Field on User Create**: `{ "id": "uid1", ..., "isAdmin": true, "accountStatus": "active", "walletBalanceRwf": 50000 }` -> Rejected by `hasOnly(...)` + initial zero/pending invariants.
2. **Unverified Admin Email Spoof**: Request with `auth.token.email == 'ezeprodeveloper@gmail.com'` and `auth.token.email_verified == false` -> Rejected by `isAdmin()` checking `email_verified == true`.
3. **Cross-User PII Read / User Scrape**: Authenticated user `uid2` attempts `get(/users/uid1)` or `list(/users)` -> Rejected by `isOwner(userId) || isAdmin()`.
4. **Member Self-Modification of Locked Photo**: Owner `uid1` updates `photoDataUrl` on `/users/uid1` -> Rejected because `photoDataUrl` is absent from all member update action branches.
5. **Member Self-Approval of KYC or Account Activation**: Owner `uid1` updates `kycStatus: 'approved'` or `accountStatus: 'active'` on `/users/uid1` -> Rejected because KYC submission enforces `incoming().kycStatus == 'pending'` and activation submission enforces `incoming().accountStatus == 'payment_submitted'`.
6. **Unbounded Wallet Credit Spoof**: Owner `uid1` updates `walletBalanceRwf: 999999` on `/users/uid1` -> Rejected by strict conservation/delta gates (`savings`, `p2p`, `fx`, `spin`, `checkIn`).
7. **ID Poisoning Attack**: Create document at `/savingsGoals/<1500-char-junk>` or `/users/uid1;drop` -> Rejected by `isValidId()` regex `^[a-zA-Z0-9_-]+$` and `.size() <= 128`.
8. **Duplicate Video Watch Claim**: User `uid1` updates `watchedByUserIds` on `/videoCampaigns/vid1` when `uid1` is already in `watchedByUserIds` -> Rejected by `!(request.auth.uid in existing().watchedByUserIds)`.
9. **Exceeding Spin Cap (> 200 RWF)**: User `uid1` creates `/spinHistory/sp1` with `rewardRwf: 500` -> Rejected by `rewardRwf <= 200`.
10. **Loan Auto-Approval or Insufficient Savings**: User `uid1` creates `/loans/ln1` with `status: 'approved'` or `principalRwf >= savingsBalanceRwf` -> Rejected by `incoming().status == 'pending_admin'` and `get()` savings balance check.
11. **Double P2P Claim / Terminal State Tampering**: User `uid2` updates `/p2pTransfers/p1` when `claimedByReceiver == true` or claims another user's transfer -> Rejected by `existing().receiverId == request.auth.uid && existing().claimedByReceiver == false`.
12. **Hidden Promotion or Settings Injection**: Non-admin user attempts `create` or `update` on `/promotions/p1`, `/settings/platform`, or `/admins/uid2` -> Rejected by `isAdmin()`.
